BÁO CÁO BỔ SUNG MÃ NGUỒN BACKEND
VÀ CẤU HÌNH CƠ SỞ DỮ LIỆU

Dự án: Sàn giao dịch ô tô — Kiến trúc microservices (NestJS)

1. Liên kết GitHub repository

Repository: https://github.com/TuanJS-TEC/Car-Marketplace-Microservices-Platform

Trong repo có mã nguồn backend (monorepo npm workspaces), thư viện dùng chung, cấu hình Docker Compose cho PostgreSQL và các dịch vụ phụ trợ, cùng các script SQL trong thư mục scripts/ và schema khởi tạo trong libs/database/index.sql.

2. Tổng quan kiến trúc backend

Dự án là monorepo Node.js (Node ≥ 20), framework NestJS, pattern CQRS ở các service nghiệp vụ chính, kết nối PostgreSQL qua TypeORM, đồng bộ schema có thể bật qua biến môi trường TYPEORM_SYNC=true (mặc định false — khuyến nghị dùng script SQL khi triển khai thật).

Các ứng dụng trong apps/:

  • api-gateway — Cổng HTTP, proxy tới listing-service, auth-service, payment-service (định tuyến /api/v1/listings, /api/v1/auth, /api/v1/payments, /api/v1/payment cho webhook).
  • auth-service — Đăng nhập, đăng ký OTP, OTP công khai, đặt lại mật khẩu; hồ sơ người bán (JWT + SellerGuard): xem/sửa profile, upload avatar, đổi SĐT qua OTP.
  • listing-service — Tin đăng xe (tạo/sửa/xóa), duyệt/từ chối/yêu cầu chỉnh sửa, tìm kiếm, lọc, so sánh, yêu thích, chia sẻ, báo cáo; quản trị: kiểm duyệt tin, xử lý báo cáo, khóa tài khoản, cảnh báo seller, gỡ tin hàng loạt (UC tương ứng trong code); upload ảnh tin và duyệt ảnh thủ công.
  • payment-service — Phương thức thanh toán, tạo đơn, polling trạng thái đơn, khởi tạo VietQR / ví / ATM (sandbox demo), webhook VietQR, ví, ATM, hoàn tiền; endpoint admin hoàn tiền.
  • user-service — API xác minh danh tính (gửi yêu cầu, trạng thái được phép bán, danh sách chờ duyệt phía admin trong controller).
  • admin-service — Duyệt/từ chối yêu cầu xác minh danh tính (kênh admin).
  • notification-service — API nội bộ gửi cảnh báo seller và thông báo khóa tài khoản (tích hợp luồng UC36/UC37).
  • search-service — Khung dự án NestJS (health/hello); tìm kiếm nâng cao có thể mở rộng với Elasticsearch trong stack Docker đầy đủ.

Thư viện dùng chung: libs/common, libs/database (TypeORM + entity user cơ bản), libs/messaging.

3. Cấu hình cơ sở dữ liệu và hạ tầng

3.1. Docker Compose

  • docker-compose.dev.yml — Môi trường nhẹ: PostgreSQL 16, Redis 7, RabbitMQ (user postgres, mật khẩu 12345, DB car_marketplace, cổng 5432).
  • docker-compose.yml — Stack đầy đủ: thêm Elasticsearch 8, MinIO; PostgreSQL user car / mật khẩu car, DB car_marketplace.

3.2. Biến môi trường kết nối DB (TypeORM)

Mặc định trong code: POSTGRES_HOST, POSTGRES_PORT, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB (database mặc định car_marketplace). Gateway dùng thêm LISTING_SERVICE_URL, AUTH_SERVICE_URL, PAYMENT_SERVICE_URL.

4. Script SQL và “migration”

Dự án cung cấp schema và dữ liệu dưới dạng script SQL (không bắt buộc dùng công cụ migration riêng nếu triển khai bằng file .sql):

  • libs/database/index.sql — Script tạo database car_marketplace, định nghĩa ENUM, toàn bộ bảng nghiệp vụ (người dùng, tin đăng, ảnh, giao dịch, gói, báo cáo, thông báo, v.v.).
  • scripts/pg-auth-schema-patch.sql — Bổ sung cột/bảng phục vụ auth-service (OTP, đăng ký chờ, cột camelCase trên users) khi TYPEORM_SYNC=false.
  • scripts/seed-sample-data.sql — Dữ liệu mẫu + tài khoản demo (admin/seller/buyer), có cảnh báo TRUNCATE — chỉ dùng dev.
  • scripts/payment-wallet-columns-patch.sql, scripts/payment-atm-columns-patch.sql, scripts/payment-refund-uc34-patch.sql — Patch cột/bảng liên quan thanh toán (ví, ATM, hoàn tiền) theo từng giai đoạn tính năng.

5. Mô tả ngắn gọn các chức năng đã làm được

  • Xác thực & tài khoản: Đăng nhập JWT; đăng ký qua OTP; gửi/xác thực OTP (đổi mật khẩu, xác thực SĐT); hoàn tất đặt lại mật khẩu.
  • Hồ sơ người bán: Xem/cập nhật thông tin; upload avatar; đổi số điện thoại có OTP.
  • Tin đăng xe: Tạo tin chờ duyệt; danh sách/chi tiết (chỉ tin đã duyệt cho người xem); sửa/xóa; duyệt/từ chối; gói đăng tin; tìm kiếm từ khóa; lọc nâng cao; so sánh tối đa 3 tin; yêu thích; chia sẻ (tăng share count); xem SĐT; link chat Zalo; báo cáo vi phạm.
  • Ảnh tin: Hướng dẫn upload, upload multipart, luồng kiểm tra/duyệt ảnh (kể cả duyệt thủ công).
  • Quản trị tin & vi phạm: Danh sách/chi tiết tin chờ duyệt; duyệt/từ chối/yêu cầu chỉnh sửa; quản lý báo cáo và xử lý (cảnh báo, gỡ tin hàng loạt, khóa tài khoản, lịch sử cảnh báo/gỡ tin).
  • Xác minh danh tính: Người dùng gửi yêu cầu; admin/user-service duyệt hoặc từ chối; kiểm tra điều kiện được bán.
  • Thanh toán: Liệt kê phương thức; tạo đơn (JWT + seller); tra cứu đơn; VietQR / ví / ATM (sandbox); webhook xác nhận thanh toán; hoàn tiền (admin).
  • Thông báo: Endpoint nội bộ gửi cảnh báo cho seller và thông báo khóa tài khoản.
  • API Gateway: Gom entry point REST cho listings, auth, payments và webhook thanh toán thống nhất.
